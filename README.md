# Process-then-Retrieve

This repository is an organized copy of the collaborative [Process-then-Retrieve repository](https://github.com/jtranx10/Process-then-Retrieve). See the papers below for the author lists.

## Repository layout

- [Python scripts](python/) includes model loading, probing, activation patching, and residual-stream analysis.
- [Notebook exports](notebook-exports/) preserves experiment files that contain notebook commands. They retain their original extensions and some cells require a notebook runtime.
- [Figures](figures/) contains figures and original captions from the arXiv preprint and ICLR workshop PDF.

## Research overview
Understanding the internal integration of visual and textual data in vision–language models (VLMs) remains a significant challenge. We present a mechanistic study of PaliGemma-3B, testing the hypothesis that the model follows a two-phase workflow where early layers prioritize textual processing, while later layers execute cross-modal retrieval. This behavior likely stems from the high semantic information of visual inputs passed on by the vision encoder, whereas text embeddings rely on early layers to build semantic context. Using representational similarity analysis, attention quantification, and residual stream attribution, we reveal that early layers preserve visual embeddings with minimal modification while focusing on text. Significant cross-modal alignment and visual attention appear only in the final layers. We find that this structural bias is the leading cause of textual dominance, where linguistic priors can override conflicting visual evidence. Our results provide a foundation for addressing the "modality gap" and offer insights into multimodal reasoning in VLM architectures.

## Experiment index

Review each script or notebook for its model checkpoint, dataset, device and input paths before running.

- [`attention_output_patching.py`](python/attention_output_patching.py): runs an attention output patching experiment to measure how different layer groups can impact the results of a simple counting prompt. The source layers and target layers can be changed depending on the desired patching combinations: early to mid, late to mid, early to late, mid to late. runs a patched forward pass where the forward hook overwrites its output with the saved activation from a source layer. computes and stores, for each image, the logit score for the correct answer token and the loss, both for clean and patched runs, along with their differences. 

- [`text-patching.py`](python/text-patching.py): runs a textual patching experiment to test how different layer textual representations can impact the results of a simple counting prompt. prepares hooks to capture and later overwrite hidden states at the source layers. The model creates labels such that only the final token is supervised with the answer token ID using `processor`. The code first runs a "clean" forward pass while saving activations from the source layers (from forward hooks), then it removes the hooks and records the clean answer logit and loss. Then, the model runs a "patched" forward pass in which forward hooks overwrite each target layer's output with the previously saved source-layer activations, and records the patched answer logit and loss. The source layers and target layers can be changed depending on the desired patching combinations: early to mid, late to mid, early to late, mid to late.

- [`vision-patching.py`](python/vision-patching.py): runs vision representation patching experiment, measuring how copying vision activations between layers can impact the results of a single counting prompt via answer logits and loss. performs clean vs. patched forward passes where source vision encoder layer activations are replaced with those from target layers, then compares the model's behavior. The source layers and target layers can be changed depending on the desired patching combinations: early to mid, late to mid, early to late, mid to late. The model creates labels such that only the final token is supervised with the answer token ID using `processor`. During the initial clean pass, the code stores clean activations from source layers. Then, during a patched forward pass, it replaces each target layer's output with the saved source layer activation. The source layers and target layers can be changed depending on the desired patching combinations: early to mid, late to mid, early to late, mid to late.

- attention-scores-contributions.ipnyb: analyzes attention pattern distributions across different input modalities in PaliGemma by extracting and visualizing attention matrices from all layers. Runs PaliGemma with PixelProse dataset to process an image with a text prompt to capture attention weights. Divides each layer's attention matrix into four sub-regions (image to image, text to image, image to text, text to text) and computes stats (mean, etc.) for each region. Visualizes individual layer attention patterns as heatmaps and region-specific attention maps. Generates cross-layer analysis via line and bar plots showing how mean attention scores in each sub-region evolve across all model layers, enabling comparison of how different modality interactions change throughout the network depth.

- [`attention-vs-mlp-contributions.ipnyb`](notebook-exports/attention-vs-mlp-contributions.ipnyb): analyzes the relative and absolute contributions of attention and MLP sublayers to the residual stream across all layers in PaliGemma, measured separately for vision and text tokens. Processes 5 randomly sampled image-caption pairs from the PixelProse dataset. Registers forward hooks on both self-attention and MLP modules in each layer to capture their outputs and the residual states before/after each component. For each layer, computes the L2 norm of attention deltas (difference between residual before and after attention) and MLP outputs separately for vision tokens (first 1024 tokens) and text tokens (remaining tokens), then calculates relative contribution percentages by normalizing against total change. Averages contributions across all 5 samples and visualizes results via stacked bar charts showing relative contribution percentages (attention vs MLP summing to 100%) and line plots showing absolute contribution magnitudes across layers. Identifies which layers are attention-dominant versus MLP-dominant for both modalities and prints summary statistics of average contributions.
  
- [`token-contributions-per-layer.ipnyb`](notebook-exports/token-contributions-per-layer.ipnyb): analyzes residual stream evolution across layers by tracking how vision and text token representations change throughout PaliGemma's forward pass. Extracts PaliGemma with hidden states then processes an image-caption pair from the PixelProse dataset. Separates the input sequence into vision tokens (first 1024 tokens) and text tokens (remaining tokens), then for each layer computes the norm of representation changes (delta between consecutive layers), total representation norms, and relative contribution percentages. Calculates cosine similarity between representations at different depth stages (initial embeddings, early layers, mid layers) and the final layer output to measure how much representations stabilize. Visualizes per-layer changes separately for vision and text tokens via line plots showing average norm of change across all model layers. Finds total changes within early, middle, and late layer groups to see total processing within each modality.
